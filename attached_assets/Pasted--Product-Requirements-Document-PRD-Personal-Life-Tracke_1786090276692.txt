# Product Requirements Document \(PRD\)

## Personal Life Tracker \- iOS App

**Version:** 1\.0

---

# 1\. Overview

Build a **native iOS application** that acts as a personal life
dashboard\. The app combines:

- Daily & recurring task management
- Expense tracking
- Nutrition tracking
- Weight tracking
- Habit streaks
- Analytics & charts
- Dashboard

The application is designed **only for personal use**, so the
architecture should remain extremely simple, lightweight, and free to
operate\.

The application **must not use Firebase, Supabase, MongoDB, PostgreSQL,**
**or any paid backend/database**\.

Google Sheets will serve as the persistent storage\.

---

# 2\. Goals

The app should replace multiple apps like:

- Apple Reminders
- Habit Tracker
- MyFitnessPal
- Expense Manager

with one unified application\.

# 5\. Food Database Behaviour

When user types:

`2 Roti`

Search FoodDatabase\.

If found:

- Calculate nutrition automatically\.

If not found:

Show dialog:

> Food not found. Please enter Calories, Protein, Carbs, Fat and Fibre.

Once user saves:

- Automatically append to FoodDatabase sheet\.
- Future searches should find it immediately\.

No manual maintenance required after first entry\.

# 15\. Authentication

Single\-user application\.

Use a Bearer Token stored securely in the iOS Keychain\.

Apps Script validates the token before processing requests\.

---

# 16\. Offline Support

Cache data locally using SwiftData\.

Workflow:

User action → Save in SwiftData → Background sync to Google Sheets →
Retry automatically if offline\.

# 20\. Development Guidelines for the LLM

- Follow MVVM\.
- Use reusable SwiftUI components\.
- Use async/await\.
- Store data locally in SwiftData and sync to Google Sheets\.
- Keep Apps Script as a thin API layer\.
- Use dependency injection\.
- Build module by module\.
- Keep architecture modular\.
- Prioritize offline\-first behavior\.
- Write clean, documented code with unit tests for business logic\.
